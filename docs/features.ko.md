# 기능

[English](features.md)

- [o] G1 — P1: soksak 0.0.2의 로컬 registry를 담는다. 2026-10-02 core checklist 항목 R1-6을 위해 만들었다. `registry.json`이 plugin repository `browser`, `files`, `terminal`과 `files`, `vt`의 sidecar 폴더를 선언하고, `packs/starter.json`이 starter pack을 정하며, `make build SOK=<sok>`가 각 repository의 `make pack`이나 `make release`를 실행해 항목을 쓰고 `sok registry build`를 실행한다. macOS arm64에서 `make test`와 `make build`가 통과한다(plugin 3, sidecar 2, pack 1).
- [~] G3 — P0: core checklist 항목 R2-5-2를 위해 CI workflow를 둔다. `ci.yml`은 `registry.json`이 선언한 대로 plugin 저장소를 이 저장소 옆에 checkout하고 macOS runner에서 `make test`를 실행하며, `.node-version`이 설치할 Node.js 버전을 선언한다. 2026-10-04 진행: `ci.yml`의 build-machine rehearsal이 macOS에서 통과했다.
- [o] G4 — P0: README를 바로잡는다. README는 저장소를 soksak 0.0.2의 로컬 registry라고 했고, 설치 명세를 GitHub에서 열리지 않는 형제 경로로 연결했으며, 게시 build와 GitHub Pages 주소가 없었다. 2026-10-04 완료: 두 README가 공개 registry, Pages 주소, publish workflow를 설명하고, core 명세를 GitHub URL로 연결하며, 로컬 build와 게시 build를 적는다. `make test`가 통과한다.
- [~] G5 — P0: core 명세 `docs/spec/registry.md`대로 공개 registry를 둔다. core checklist 항목 R2-4-4를 위한 것으로, commit한 항목 파일, 규칙마다 테스트를 둔 `scripts/validate.mjs`, workflow `validate.yml`, `publish.yml`, `CODEOWNERS`, `CONTRIBUTING.md`를 두고, `registry.json`, `scripts/build.mjs`, `ci.yml`의 형제 checkout을 없앤다. 이 항목은 G2를 대신한다. G2의 게시 build는 soksak 저장소의 release tag만 모았으므로, 저장소는 component를 형제 폴더로 가리켰고 누구도 그것으로 설치하거나 plugin을 더할 수 없었다. 2026-10-04 진행: 테스트 12개를 둔 `scripts/validate.mjs`(`make test`), workflow 세 개, `CODEOWNERS`, `CONTRIBUTING.md`, README가 있고, `registry.json`, `scripts/build.mjs`, 생성된 로컬 파일을 없앴다. rehearsal은 build-machine이 자기 저장소의 ref checkout, `workflow_run`, `workflow_call`, `actions/download-artifact`를 지원하기를 기다린다. soksak 항목을 등록하는 계정은 `soksak-app`의 공개 member여야 한다.
- [o] G6 — P0: component release로 항목에 version을 더한다. core checklist 항목 R2-4-5를 위한 것으로, `node scripts/add-version.mjs plugin|sidecar`는 plugin이나 sidecar 폴더의 package와 release archive를 읽어, 새 version, 그 저장소의 GitHub release asset URL, 각 archive의 `sha256`을 담은 항목 파일을 쓴다. 게시한 version은 바뀌지 않으므로 이미 있는 version은 거부한다. component release workflow와 외부 기여자가 쓴다. 2026-10-04 완료: `test/add-version.test.mjs`(테스트 3개, 쓴 항목은 `checkEntry`를 통과)와 함께 `scripts/add-version.mjs`를 두었다. `make test`가 테스트 15개로 통과하고, CONTRIBUTING이 script를 적는다.
- [o] G7 — P0: plugin version의 sidecar 범위를 그 `plugin.json`의 `dependencies`에서 읽는다. `package.json` `soksak.sidecars`를 그것으로 바꾸는 core checklist 항목 F26을 위한 것이다. 2026-10-04 완료: `add-version.mjs`가 항목의 `sidecars`를 `plugin.json` `dependencies`로 쓴다. `make test`가 16/16 통과하고, 새 test는 변경 전 범위 대신 `{}`로 실패했다.
- [o] G8 — P0: core checklist 항목 R2-4-5를 위해 registry 관리자가 pull request를 merge하고 soksak 항목을 push하게 한다. `merge.yml`과 `validate.yml`의 검사한 commit 기록을 지우고, `publish.yml`은 `main`으로의 각 push에서 게시한다. 2026-10-05 완료: `make test`가 통과한다.
- [o] G9 — P0: shell을 UTF-8 locale로 실행하는 terminal plugin 0.0.6과 terminal service 0.0.6을 등록한다. core checklist 항목 F101.2를 위한 것이다. 2026-10-08에 완료했다. 항목은 릴리스된 archive의 sha256을 담고 그 값은 릴리스 `SHA256SUMS`와 일치한다. `make test`와 `make build`가 통과한다.
- [o] G11 — P1: core `v0.0.6`의 `sok`으로 index를 검사하고 build한다. core checklist 항목 F102.1.4를 위한 것이다. 그 `sok registry build`는 각 plugin archive의 `plugin.json`을 읽어 index에 sidecar 의존만 적고, 목록의 어떤 version도 채우지 않는 plugin 의존에 실패한다. 2026-10-08에 완료했다. `validate.yml`과 `publish.yml`이 `CORE_RELEASE: v0.0.6`을 선언한다. 이를 담은 push의 publish workflow가 그것으로 index를 build하고 게시했다.
- [o] G12 — P1: text 파일을 읽고 쓰는 files sidecar 0.0.4와, tree에서 `core.file.open`으로 파일을 여는 files plugin 0.0.5를 목록에 올린다. core checklist 항목 F102.2와 F102.4를 위한 것이다. 2026-10-08에 완료했다. 항목은 릴리스된 archive의 sha256을 담고, 이는 sidecar release의 `SHA256SUMS`와 맞으며, 게시된 index가 files 0.0.5와 `@soksak/sidecar-files` 0.0.4를 나열한다.
- [o] G13 — P1: 프로젝트의 text 파일을 CodeMirror로 여는 편집기 plugin 0.0.1을 목록에 올린다. core checklist 항목 F102를 위한 것이다. 2026-10-08에 완료했다. 항목은 릴리스된 archive의 sha256을 담고, 게시된 index가 `engines.soksak` `>=0.0.7`과 files sidecar `^0.0.4`를 가진 editor 0.0.1을 나열한다.
